07 — DATA REQUEST SENSE (pin 2 → MCU)
=====================================

WHAT THIS BLOCK IS
------------------
When the OSM wants telegrams, it drives RJ12 pin 2 HIGH (~4.0–5.5 V).
Your MCU must DETECT that and start UART TX. When OSM releases pin 2
(high‑Z), stop sending.

You NEVER drive pin 2 from the MCU.

CHOSEN APPROACH (THIS BUILD)
----------------------------
**Optocoupler / digital isolator** (see circuit 11) — DSMR-like.

Fallback for bring-up only: resistor divider (10k/10k) if opto not stuffed.

NECESSARY PIECES
----------------
1. Opto LED path on P1 / Request side (series resistor).
2. Opto output into 3.3 V GPIO (pull-up to VCC_3V3 as needed).
3. ESD (circuit 09).
4. Firmware: interrupt or poll → gate telegram stream.

RECOMMENDED PARTS
-----------------
- TLP2361 / 6N137 / Si86xx — prefer over PC817
- Series LED resistor sized for CTR + speed
- Document active-high vs active-low after opto

KICAD
-----
Nets: P1_REQ (RJ12), P1_REQ_MCU (GPIO).
Silk: "REQ IN".

TEST
----
Float pin2 → MCU inactive.
Apply 5 V on pin2 → MCU active → start send. Remove → stop.
