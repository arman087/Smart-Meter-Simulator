07 — DATA REQUEST SENSE (pin 2 → MCU)
=====================================

WHAT THIS BLOCK IS
------------------
When Ghost / OSM wants telegrams, it drives RJ12 pin 2 HIGH (~4–5.5 V).
MCU must DETECT that and start UART TX. When pin 2 goes high‑Z, stop.

You NEVER drive pin 2 from the MCU.


TWO VOLTAGE DOMAINS (this is the whole point of the opto)
----------------------------------------------------------
  P1 / RJ12 side     ≈ 5 V   (Request comes from Ghost)
  MCU side           = 3.3 V (ESP32 GPIO only)

The opto LED sits on the 5 V Request path.
The opto transistor sits on the 3.3 V GPIO path.
They only couple by light — GPIO never sees 5 V.


EXAMPLE WIRING
--------------
  RJ12 pin2 (P1_REQ)
       │
      Rser (size for ~5–10 mA LED; start ~470 Ω–1 kΩ, check CTR)
       │
       ▼
    opto LED anode
    opto LED cathode ── GND

    opto collector ──┬── Rpu (10 kΩ) ── VCC_3V3
                     └── ESP32 GPIO (e.g. free input)
    opto emitter ── GND

Polarity: document whether GPIO is HIGH or LOW when Request is active
(depends on transistor wiring). Firmware gates TX on that level.


PARTS
-----
**Locked pick (same type for Request + Data): high-speed logic opto with open-collector output**

| Qty | Part | Brand | Why |
|-----|------|-------|-----|
| **2** | **6N137** (SMD: e.g. **6N137SDM**) | **onsemi** (or Vishay / Broadcom HCPL-2611) | **10 MBd**, open-collector VO — correct for pin 5 Data; Request uses VO + pull-up to 3.3 V |
| 1 | Optional dual | **Vishay VO2630** / Broadcom **HCPL-2631** | Same speed, **two channels in one IC** |

Search LCSC: `6N137SDM` or `6N137` SOIC-8. Prefer **onsemi / Vishay / Broadcom** — not no-name.

**Premium modern SMD (Toshiba)** — great for Request, **not** alone on pin 5:
  Toshiba **TLP2361** — LCSC **[C123773](https://www.lcsc.com/product-detail/C123773.html)** — 15 Mbps, 2.7–5.5 V VCC.
  Output is **totem-pole (inverted)** → fine into a GPIO; for Data add **BSS138** (drain → pin5) so you stay open-drain.

Do **not** use PC817 / EL817 for Data @ 115200.

Always put **100 nF** between VCC and GND of each 6N137 / TLP2361, right at the package.


KICAD
-----
Nets: P1_REQ, P1_REQ_MCU.
Place near RJ12. Silk: REQ.


TEST
----
Float pin2 → MCU idle (no TX).
Apply ~5 V on pin2 → MCU sees Request → start send. Remove → stop.

FIRMWARE
--------
See ../../FIRMWARE_GUIDE.md
Locked nets: RJ12_pin2 → 330 Ω → U9 → ESP32_enable (10 kΩ to 3V3).
Request active = ESP32_enable LOW. Tie that net to a free GPIO and record it in FIRMWARE_GUIDE.md.
